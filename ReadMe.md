# Архитектура InsureTech

## Описание компании

Компания занимается предоставлением агрегированных страховых услуг. Она работает как с частными, так и с корпоративными клиентами:

* для физических лиц предлагается удобный онлайн-сервис, позволяющий подобрать и оформить страховку,
* бизнес-клиентам и партнёрам предоставляется API, через которое они могут интегрировать страховые продукты в свои собственные решения.

На текущий момент основной продукт InsureTech — страхование жизни.


## Проблемы компании

После успешного запуска MVP приложение компании быстро набрало популярность, но вместе с ростом столкнулось с типичными трудностями масштабирования:

* **Медленная загрузка сайта.** При увеличении нагрузки пользователи начали массово жаловаться на то, что страницы открываются по несколько минут или вовсе не загружаются. Зафиксированный максимум нагрузки составил 50 RPS на поисковые запросы и 10 RPS на оформление заявок. Такая производительность негативно влияет на показатели NPS и удержание клиентов.
* **Нарушение SLA у B2B-клиентов.** Партнёры неоднократно сообщали, что API не соответствует заявленным SLA. При анализе инцидентов выяснилось, что в моменты сбоев один из партнёров значительно превышал согласованную нагрузку — до 250 RPS по всем операциям вместо оговорённых 20 RPS. В итоге этот партнёр фактически занимал все ресурсы приложения.
* **Падения приложения.** InsureTech уже несколько раз сталкивалась с полной недоступностью сервиса. Проблема усугубляется тем, что команда поддержки узнаёт о сбое только после жалоб пользователей. Каждый час простоя обходится бизнесу примерно в 500 тысяч рублей прямых убытков, не считая репутационных потерь: появляются негативные публикации в СМИ, снижается удовлетворённость пользователей, а некоторые партнёры заявляют о намерении не продлевать сотрудничество.

В ближайшее время InsureTech собирается запустить масштабную рекламную кампанию, и ожидается существенный рост пользовательской базы и трафика.


## Архитектура приложения

Основные элементы текущей системы:

* **core-app** — монолитное серверное приложение, которое отвечает за показ клиентам доступных страховых продуктов, оформление новых заявок и отображение уже купленных страховок.
* **client-info** — сервис управления клиентскими данными. Передаёт информацию в core-app при оформлении страховок. Если клиента нет в базе или его данные изменились, сервис добавляет или обновляет их. Также он обеспечивает просмотр и редактирование данных в личном кабинете пользователя.
* **ins-product-aggregator** — интеграционный сервис, получающий данные о страховых продуктах от разных компаний. Кроме того, он делает запросы по ОСАГО к нескольким партнёрам, формируя единый API для получения предложений от всех страховых компаний.
* **ins-comp-settlement** — сервис взаиморасчётов со страховыми компаниями. Раз в месяц он отправляет список оформленных полисов для расчёта агентских вознаграждений.
* **Web-App** — клиентское веб-приложение для пользователей сервиса.

Развёртывание всех компонентов выполняется в Kubernetes-кластере, который размещён в одной зоне доступности.

В качестве СУБД используется PostgreSQL. Каждый сервис имеет собственную схему данных в общей базе. База развёрнута на отдельной виртуальной машине и существует в единственном экземпляре.

Фронтенд взаимодействует с бэкендом через REST API.

Партнёрские интеграции работают через API, доступный во внешней сети через Kubernetes LoadBalancer.

Бэкенд подключён к пяти страховым компаниям.
